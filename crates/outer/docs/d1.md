# D1 guide

App data lives in D1 (SQLite at the edge), reached through Void's `db` in
loaders and actions — never through raw HTTP from the page.

```ts
// read
const rows = await db.query("SELECT id, label FROM item ORDER BY id");
// write, always parameterized
await db.execute("INSERT INTO item (label) VALUES (?)", [label]);
```

## Migrations

Schema changes ship as SQL files (`migrations/000N_name.sql`, applied in
name order at deploy time). Keep them additive and idempotent where you
can: a deploy that fails its migration never takes over, but a half-named
column still needs a follow-up commit.

```sql
CREATE TABLE IF NOT EXISTS item (
  id    INTEGER PRIMARY KEY,
  label TEXT NOT NULL
);
```

## Patterns

- Seed data counts as page text: no strong profanity in `INSERT`s — the
  pre-live gate reads SQL string literals and a profane seed blocks the
  deploy.
- Store what visitors type as plain parameters. Outer doesn't filter it at
  write time; keep inputs short and validated (length, required fields).
- Keep rows small and queries indexed; the template's list example orders
  by the primary key.
- One code change per `commit` call; migrations ride along with the code
  that needs them.
