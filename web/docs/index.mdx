Outer is a personal software forge for AI agents. You tell your agent what
you want — "make my family a grocery list app" — and it builds the app and
gets back a live `https://<slug>.outer.now` link you can share.

## Core concepts

Three terms, used everywhere in these docs:

- **App** — an Ilha + Void web app, live at `https://<slug>.outer.now`.
  Unlisted by default: anyone with the link can visit, nobody can find it
  by browsing.
- **Agent** — your AI agent (Claude, Codex, ChatGPT, …), connected to Outer
  over MCP. The agent writes the code, ships it, and reads back the result.
- **Deploy** — one shipped change. Every change waits for its deploy and
  reports back: `success` with the URL, `failed` with the log tail, or
  `blocked` with the exact lines to fix.

## The core loop

<Steps>
<Step title="Connect your agent">
Point it at `https://outer.now/mcp` — one line per client in [Connect](/connect).
Sign-in is one OAuth approval, or an emailed code for clients without OAuth.
</Step>
<Step title="Ask for an app">
"Make a grocery list app for my family." Your agent calls `create_app` and
a live Ilha + Void app serves in seconds.
</Step>
<Step title="Refine it">
"Add a filter for who bought what." Every change ships through the same
loop: build, review, deploy — the previous version keeps serving until the
new one is healthy.
</Step>
<Step title="Share the link">
Your agent returns the URL plus a QR code for the family chat
(`share_app`). Open the [Console](/console) to see what it built.
</Step>
</Steps>

## What you can build

Anything the Ilha + Void template can express, backed by D1, KV, Durable
Objects, R2, queues, cron and realtime: family tools, sign-up sheets,
dashboards, games, chat rooms, scheduled digests. Concrete starters with
copy-paste prompts: [What you can build](/what-you-can-build).

:::note
Outer is in closed beta. New accounts need an invite code (`OUTER-XXXX-XXXX`) —
if your email is not allowed in yet and you have no code, sign-in tells you
that you are on the waitlist. [Sign in](/sign-in) has the details.
:::

## Get help

- Ask your agent first — it reads these docs over MCP (`docs` tool) and
  relays any `user_message` from a refusal verbatim. Those messages are
  written for you; don't let it improvise around them.
- Deploy stuck? [FAQ and troubleshooting](/faq) covers the common failures:
  sign-in, blocked deploys, held apps, sleeping fleets.
- Prompting tips — how to ask so your agent gets it right the first time:
  [Prompting your agent](/prompting).
