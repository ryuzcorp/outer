One Outer account is one email address. There are two ways in, both ending
at the same account.

Your agent does the technical steps. The agent version lives at Agents → [Quickstart](/agents/start-here/quickstart).

## OAuth apps

These clients sign you in with OAuth: Claude, Codex, ChatGPT, Gemini,
and Perplexity. Your client opens Outer's sign-in page:

1. Enter your email. During the closed beta, an email that is not allowed in gets "Outer is in closed beta. Ask someone on Outer for an invite code, or you're on the waitlist." Paste an invite code (`OUTER-XXXX-XXXX`) into the "Have an invite code?" field instead.
2. Enter the 6-digit code from your inbox.
3. On first sign-in only, accept the Terms and Privacy Policy.
4. Approve the client: "Allow Claude (claude.ai) to act as you on Outer?" — read your apps' code, database rows, logs and live pages; create, change, deploy and delete apps, or delete your whole account; set app secrets, API keys, sharing, visitor access and custom domains; see and revoke your other connections to Outer; and email people you name, such as collaborator invites. It cannot change your plan or pay for anything; billing stays in the console.

The client retries the call with its new token. You can revoke a client any
time on the Console's Connections and keys page, or by asking your agent.

## Without OAuth: the /keys page

For scripts, older clients, and agent harnesses without OAuth, sign in on the
web and copy an API key from [Keys](https://outer.now/keys):

1. Open [Keys](https://outer.now/keys). It sends you to the sign-in page first: enter your email. Outer emails a 6-digit code (10-minute expiry, 5 attempts). During the closed beta, a new email that is not allowlisted also needs an invite code.
2. Enter the code from your inbox. On first sign-in, accept the Terms.
3. Optionally name the key, then select "Create API key". It is shown once.
4. Add it to your MCP config or script as the `Authorization: Bearer` header.

The key is only a credential. Your agent cannot sign you in or mint keys over
MCP: there are no sign-in or key tools on the endpoint.

## Invite codes

Outer is in closed beta. New emails need an invite code (`OUTER-XXXX-XXXX`)
to join. Joiners get 3 codes of their own to share, shown on the Console's
Invites page. Collaborators and allowlisted emails get in without a code
and get none. A code admits one new account and is spent when
that account signs in. Allowlisted and existing emails never burn one. Admins
generate codes in bulk from the Console's Admin page instead of getting
automatic ones.

## API keys

1. Create a key at [Keys](https://outer.now/keys), or in Console → Connections & keys. It is shown once, so store it now.
2. List keys in the Console; `list_api_keys` shows the same ids, names, and prefixes, never secrets.
3. Revoke a key by its prefix in the Console, or with `revoke_api_key`.

## Review accounts

Some accounts are listed by the operator for directory review. A listed
email signs in with a password instead of an email code: the sign-in page
and the OAuth page both show a "Review account? Sign in with a password"
form below the email form, and no code is ever sent to a listed address.
The OAuth steps after sign-in are the same (terms on first use, then
consent).

Operators seed a review account and its demo apps with
`outer seed demo --owner EMAIL [--url URL]`, run while the server is up. The
email must be in `OUTER_REVIEW_LOGINS`; the command makes the account Pro,
accepts the current terms, then signs in to the running server over MCP and
creates two small D1-backed apps (notes and tasks), committing their pages
and migration and waiting for each deploy. `--url` names the platform when it
is not the configured origin; on localhost that is usually
`--url http://outer.localhost:8080`. Running it again leaves an app alone when
its last deploy succeeded and it still carries the demo migration, and
recommits one whose deploy failed or lost it. Password hashes come from
`outer hash-password`, which reads the password on standard input.
